## T1 筆フォントの適用

現状: 筆系の `OmikujiBrush`(Yuji Syuku)は、おみくじだけが遅延ロードして使っている。ほかは明朝(`Shippori`/`ShipporiBold`、`SERIF` 定数)で、筆感がない。

```
目的: 見出し・タイトル・ボタンのラベルに、すでに導入済みの筆フォントを使う。

やること:
1. src/fonts/useOmikujiBrushFont.ts の遅延ロードをやめ、App.tsx の useFonts に
   筆フォントを登録して起動時に読み込む(Yuji Syuku の既存パッケージを使う。新規追加はしない)。
   おみくじの既存の使い方は壊さない(名前 'OmikujiBrush' を維持するか、参照側をすべて直す)。
2. 用途別の定数を src/components.tsx に追加する(例: BRUSH)。SERIF はそのまま残す。
3. 筆にする対象: 画面見出し、セクションタイトル、ボタンや札のラベル、タブ・セグメントの文言、
   ポップやシートのタイトル、吹き出しではなくキャラの名前表示。
4. 筆にしない対象(例外・可読性優先): 数字(歩数、ポイント、回数、日付)、
   fontSize が 13 未満の補助テキスト、長い本文や説明文、入力欄、法的文言。
5. 筆フォントは字幅が変わるため、変更後に文言が切れたり折り返しで画面が溢れたりしないか、
   全画面を確認する(特に固定幅のボタン、タブ、札)。溢れる箇所は fontSize を最小限だけ下げて調整する。
   ただし fontSize の下限は 11 を守る。
6. 変更ファイルは、触ってはいけないファイル以外の全 .tsx が対象。

完了条件: 主要画面(ホーム、御朱印帳、お出かけ、コレクション、設定)で対象の文字が筆になり、
数字と小さな補助テキストは元のまま。型チェックが通る。
```

## T2 設定シートを縦スクロール可能にする

対象: 設定ボタンを押して開く画面(`src/components/AccountCenter.tsx` が中心)。

```
目的: 設定シート内を縦スクロールできるようにする。項目が増えても下が見切れない。

やること:
1. 設定シートの本文を ScrollView にし、縦スクロール可能にする。
2. 見出しと閉じるボタンは固定(スクロールで隠れない)にする。
3. 下端に SafeArea 分の余白を取り、最後の項目がホームインジケーターに隠れないようにする。
4. スクロールバーは非表示。スクロール端の見切れ表現は、既存の和紙調を壊さない最小限にする。
5. 他の画面のスクロールなし方針は変えない。この設定シートだけが例外。

完了条件: 画面が小さい端末(高さ667px相当)でも、最後の項目まで届く。既存の見た目が変わっていない。
```

## T3 チュートリアルに「引っ張り」と「モビメニュー」を組み込む

対象: `src/components/TutorialSpotlight.tsx` と、チュートリアルの定義がある箇所(App.tsx などを検索して確認)。

```
目的: 初回起動のチュートリアルで、次の操作を説明する。
- モビーのほっぺを引っ張ると、伸びて反応が返ること。
- ペットモビー(画面上を動くモビー)をタップするとメニューが開くこと。
- ペットモビーはドラッグで好きな場所に動かせること。
- ホームのモビーをタップすると、二礼二拍手一礼のお参りをすること。

やること:
1. 既存のチュートリアルの構造(ステップ定義、スポットライトの対象の指定方法)を確認し、同じ形式でステップを追加する。
2. 各ステップは短い文(1〜2行)。文体は既存のチュートリアルの口調に合わせる。
3. スポットライトの対象は、それぞれの操作対象(ホームのモビー、ペットモビー)。対象の位置が取れない場合は、既存の方式に従う。
4. ステップの追加位置は、ホームの説明の直後。全体の長さが増えすぎないよう、既存の重複説明があれば統合する。
5. すでにチュートリアルを完了した人には、再表示しない(既存の完了フラグを再利用する。別キーを増やす場合は、なぜかを説明する)。

完了条件: 初回起動で追加ステップが表示され、スキップと完了が従来どおり動く。
```

## T4 コレクション画面の見切れの調査と最小修正

```
目的: コレクション画面で、「展示室」などの切り替えボタンが切れて見える問題を直す。

やること:
1. src/components/CollectionGallery.tsx と、切り替えボタンを描画している側(App.tsx を検索)を調べる。

   幅が 360 / 390 / 430 の3種類で、ボタンが切れていないか確認する。
3. 切れの原因(固定幅、overflow: hidden、ボタン数に対する幅不足など)を特定し、
   見た目のスタイルを変えずに、レイアウトだけを直す(幅の計算、折り返し、フォント縮小の下限を11に)。
4. 画像やデザイン刷新はしない(別作業)。

完了条件: 3つの幅で全ボタンが切れずに読める。原因と修正内容を報告する。
```
