# コレクション展示室 修正設計書

更新日: 2026-09-26  
対象: コレクションタブの「コレクション」展示画面  
状態: 実装前の設計

## 1. 目的と完成像

展示室の背景に描かれたフックと棚を使い、キーホルダーを掛け、御朱印を立てかける。背景、展示品、接地表現を一つの展示ページとして扱い、端末幅が変わっても接点がずれないようにする。

**縦方向の背景は１ページにつき１枚の連続した絵とする。** 上下に別画像を継ぎ足したり、同じ画像を縦に反復したりしない。画像の途中を切って別の画像へ切り替わったように見せない。既存の `collection-room-home-harmony-v1.png`（1024 × 1536）の天井側から畳側までを一続きで表示する。

```
固定ヘッダー
┌──────────────────────────┐
│ 展示ページの上端・梁       │
│ フック + キーホルダー      │  ← 同じ背景画像・同じ座標系
│ 棚 + 御朱印               │
│ 展示ページの下端・畳       │
└──────────────────────────┘
固定ナビ
```

ヘッダーとナビはアプリの操作部として展示絵と明確に区切る。画像が画面の余白を埋めるためだけに引き伸ばされたり、別の画像につながったりする表現は使わない。

## 2. 現状と修正対象

| 箇所 | 現状 | 修正方針 |
| --- | --- | --- |
| `App.tsx` の `CollectionBackdrop` | 展示室画像を画面背面に複数枚並べ、縦スクロール量から位置を変える | 「コレクション」展示中は展示ページの背面に同じ絵を重複表示しない。操作部の背面は絵から採った単色で処理する |
| `CollectionGallery.tsx` の `CollectionBackdrop` | 背景を画面幅ごとに並べ、`stretch` で任意の室内高さへ変形する | 横ページごとに元画像を１枚使い、縦横を同じ倍率で拡大縮小する |
| `CollectionRoom.web.tsx` / `.native.tsx` | 背景とは別の３Ｄ枠・フック・台座を描画する | 背景に描かれた梁・フック・棚を位置の基準にする。必要な奥行きは小さな影・前縁・御朱印の傾きで足す |
| 展示品の位置 | 室内高さに対する係数と固定ピクセル値で決まる | 元画像上の接点座標から決める |

横に長い74地点分の展示は、１枚の巨大画像を作らず、**横ページ単位で同じ展示室の１枚絵を使う**。ページが横に切り替わることは明確な展示の切り替えとし、縦方向に画像の継ぎ目を作らない。

## 3. 画像と座標の契約

背景画像の原寸を設計座標 `1024 × 1536` とする。各ページの描画幅を `pageW` とし、倍率 `s = pageW / 1024`、描画高さ `pageH = 1536 × s` とする。背景画像と、その上の展示品・影・前縁は同じ `pageW × pageH` の親ビュー内に置く。

```ts
const DESIGN_W = 1024;
const DESIGN_H = 1536;
const scale = pageWidth / DESIGN_W;
const pageHeight = DESIGN_H * scale;
const px = (designX: number) => designX * scale;
```

- 背景は `contain` 相当の等倍比率でページ全面に表示する。`cover` による上下の欠落と `stretch` による棚・フックの変形は使わない。
- 各展示品は画像の外枠でなく**接点**を基準にする。キーホルダーは上部リングの中心をフック中心へ、御朱印は下端の接地線を棚の上面へ合わせる。
- 元画像のフック中心と棚の高さを一度だけ計測し、`collectionSceneLayout` などの定数に記録する。標準表示では中央寄りの３フック、拡大表示では中央フックを使う。実測値は元画像と実画面の重ね表示を見て確定し、表示モード別の場当たり的な補正値を増やさない。
- 透明PNGの余白による見かけのずれは、各素材の接点オフセットとして定義する。画像の種類が違っても接点の意味をそろえる。
- 前縁・接地影・御朱印の傾きは同じ親座標内で描く。装飾は展示品のタップを妨げないよう `pointerEvents="none"` とする。

## 4. レスポンシブとスクロール

| 条件 | 表示 |
| --- | --- |
| 狭い端末 | 展示ページを利用可能な幅に合わせて縮小し、高さを同倍率で決める。タップ領域は絵の大きさと別に十分確保する |
| 縦に短い端末 | 背景画像を切らず、既存の縦スクロールで１枚絵の下部まで見られるようにする |
| 大きい端末・Web | 既存のアプリ最大幅480pxの内側でページを中央配置する。画像の縦横比を変えない |
| 画面回転・サイズ変更 | 新しい `pageWidth` から背景と全接点を再計算し、現在見ている地点を保つ |

縦スクロールは `App.tsx` の外側スクロールを使う。展示ページ内に別の縦スクロールを作らない。画像より余る画面領域は展示絵の額縁・操作部として扱い、別画像を継いで埋めない。反対に画像が長い画面では、下端の畳までスクロールして見られる。

横スクロールは背景・展示品・接地表現を**同じページビュー**に入れて動かす。背景だけを `scrollX` や別アニメーションで追従させない。縦スクロール中も背景と展示品の相対位置は固定する。

## 5. 展示モードと操作

| モード | １ページの内容 | 配置 |
| --- | --- | --- |
| `standard` | ３地点 | 画像の中央寄りの３フックと棚上の３接点に、それぞれキーホルダーと御朱印を置く |
| `close` | １地点 | 中央フックと棚中央に大きめの展示品を置く |

既存の左右スワイプ、ピンチによる２モード切り替え、キーホルダー詳細、未獲得表示、所持数・キラキラ、御朱印帳表紙やパスの導線は維持する。モードを切り替える際は先頭へ戻さず、現在見ている地点を含むページへ移す。最終ページが３件未満なら空き位置は空のままにし、架空の展示品を複製しない。

横ページは必要な範囲だけ描画する。実装候補は `FlatList` の水平ページ送りで、各ページに１枚の背景と１件または３件の展示品を収める。ページの再利用時にも画像・アイテム・影が別フレームで遅れて動かない構造にする。

## 6. 実装順序

1. 元画像のフック中心、棚上面、PNG内のリング・下端接点を実測し、設計座標として記録する。
2. １ページの共通コンポーネントを作り、背景１枚と３件／１件の展示品を同じ親ビューへ配置する。
3. 背景と重なる３Ｄ展示セットを外し、必要な接地影・前縁のみを追加する。御朱印が棚に立てかかり、キーホルダーがフックから吊られた見た目を保つ。
4. ギャラリーの横ページ送りとモード切り替えを置き換え、表示中の地点・詳細操作を引き継ぐ。
5. 展示画面で二重になる `App.tsx` の背景画像レイヤーを整理する。他の「御朱印」「ミニチュア」「パス」画面に影響を広げない。

## 7. 受け入れ条件

- 背景の梁から畳までが１枚の連続した画像として見え、縦方向に画像の継ぎ目・反復・不自然な伸びがない。
- `standard` の３件と `close` の１件で、リングがフック、御朱印の下端が棚に接して見える。横スワイプ中も接点が離れない。
- 狭い端末、縦に短い端末、480px幅のWeb表示、画面回転後で、画像の縦横比と接点が保たれる。縦に短い画面でも畳まで到達できる。
- 横ページ移動、ピンチ、詳細の開閉、未獲得状態、所持数、最後の端数ページが操作できる。
- 実機またはエミュレーターとWebで、標準・拡大の両表示を実画面で確認する。背景と展示品が同時に動くことを動画または連続スクリーンショットでも確認する。

## 8. 範囲

この文書はコレクション展示画面の修正設計であり、現時点ではアプリの描画コード・画像素材を変更しない。既存の画像を使って配置を先に確定し、接地表現に不足がある場合のみ追加素材を作る。
