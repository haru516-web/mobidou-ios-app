# 依頼書B: 2礼2拍手1礼スプライトシートの再生成（全21体）

別セッション・別担当で、歩行（依頼書A）と並行して進められる。この文書だけで完結する。

## 1. 何が問題か

現行の `assets/mobies/prayer-v2/{id}/source.png`（上段=礼8コマ、下段=拍手8コマ）には次の不具合がある。

- **左右の端が切れている**コマがある（手・耳・しっぽ・持ち物がコマの端で欠ける）。
- **持ち物が一部のコマで消える**。例: もびりんは、拍手のコマだけ手に持っているパイプが消える。
- そのほか、コマごとの縮尺・位置・造形のばらつきがある。

## 2. 作るもの

対象は全21体（歩行と同じ）。キャラの同一性の基準は通常画像（`assets/mobies/{id}.webp` / `.png`。`scripts/prayer-sources-all.json` に対応表）。

| 区分 | id |
|---|---|
| 通常17 | mobirin mobichi yami mobiyan mobiyura reomoby potemoby mobibou babumoby bearmobby boymobby dogmobby ojimobby reamobby shikamobby uyumobby wolfmobby |
| イベント4 | shotamobby satomimobby norikomobby yasumobby |

### 仕様

- **8列 × 2行のシート1枚（`source.png`）**。1コマは正方形**512 × 512 px以上**（シートは 4096 × 1024 px 以上）。実アルファ透明。
- **キャラは各コマの中央70%の幅の中に収まる**（左右とも15%以上の余白）。礼で頭を下げて前に出る・拍手で腕を広げる・
  耳やしっぽ・持ち物が伸びる、いずれの最大到達点でもこの範囲を出ない。
- 全コマで同じ縮尺、足元の接地線が全コマで同じ位置。縮尺や背丈を礼の途中で伸ばし縮みさせない。

**上段（礼）8コマ**

| コマ | 内容 |
|---|---|
| 1 | 直立（通常画像と同じ姿勢・位置） |
| 2 | 軽く頭を下げ始める |
| 3 | 約25度の礼 |
| 4 | 約45度の深い礼 |
| 5 | 最も深い礼（頭頂が見え、目は下向き） |
| 6 | 起き上がる |
| 7 | ほぼ直立 |
| 8 | 直立（コマ1と同一姿勢） |

**下段（拍手）8コマ・1枚で1回の拍手**

| コマ | 内容 |
|---|---|
| 1 | 腕を下ろして直立（通常画像と同じ） |
| 2 | 両手を胸の高さに上げ、左右に離す |
| 3 | 手が近づく |
| 4 | 手のひらが合わさる（接触＝音のタイミング） |
| 5 | 接触したまま保持 |
| 6 | 手が離れる |
| 7 | 腕を下ろす |
| 8 | 直立（コマ1と同一姿勢） |

アプリは「礼 → 礼 → 拍手 → 拍手 → 礼」と同じ行を繰り返して再生する（`src/data/prayerAtlasesV2.ts`）。
そのため**各行の1コマ目と8コマ目は同じ姿勢**で、つないでも飛ばないこと。
- 座り姿勢のキャラは座りのまま礼・拍手をする。立たせない。
- 礼は体を本当に曲げる。画像の拡大縮小や回転で代用しない。

## 3. 審査基準（すべて満たすこと。1つでも外れたら不合格）

### A. 見切れ・写り込み
1. **全16コマで、不透明ピクセルがコマの中央70%の幅の外にない**（端から15%以上の余白）。
2. 全16コマで、上端・下端から16px以内に不透明ピクセルがない（頭頂・足元を含む）。
3. コマ内の最大の連結成分以外に不透明ピクセルがない（隣のコマの断片・ごみ点なし）。
4. コマ間に線・段差・色の帯がない。

### B. 持ち物・同一性
5. **持ち物・装飾品が16コマすべてにあり、形と位置関係が変わらない**。
   手に持つもの（もびりんのパイプ等）は、拍手中も持ったまま。両手を合わせるとき、持ち物は
   - 片手で持ち続けるキャラ: 持ち物ごと手が合わさる位置にくる（身体の前で持った形）。
   - 持ち物の都合で合掌できないキャラ: 持ち物は持ったまま、拍手の動作は空いている手と体の動きで表す。消さない。
6. 毛色・顔・目（カメラレンズの目）・十字ボタン・衣装・体型が通常画像と同一。コマごとに別人になっていない。
7. 帽子・リュック・マント・キーホルダー・鈴・耳飾りなどが、礼で前傾しても外れない・消えない・左右が入れ替わらない。

### C. 動き・縮尺
8. 全コマで同じ縮尺（コマ1の体高に対し、立っているコマは±3%）。接地線は全コマで±3px。
9. 体の中心の左右のずれは±8px以内（礼で重心が前に出るのは自然な範囲）。
10. 礼の最深コマで、頭が体より下がっている（45度以上）ことが目で分かる。拍手の接触コマで、両手が合わさっている。
11. 上段・下段とも、コマ1とコマ8が同じ姿勢。

### D. 技術
12. PNG、RGBA、実アルファ。チェッカー模様を焼き込まない。縁のハロー・白フチなし。
13. 8列×2行が等分（コマ境界で分割して崩れない）。

## 4. 納品と自己審査

- 納品物: `{id}/source.png`（8×2）。
- キャラごとに自己審査表を埋めて添付する。空欄があるものは受け取らない。

```
id: ____
A1 中央70%に収まる [OK/NG]   A2 上下16px以内に不透明なし [OK/NG]   A3 断片なし [OK/NG]   A4 線・帯なし [OK/NG]
B5 持ち物が全16コマにある [OK/NG]   B6 同一性 [OK/NG]   B7 装飾品が外れない [OK/NG]
C8 縮尺・接地線 [OK/NG]   C9 中心ずれ [OK/NG]   C10 礼の深さと拍手の接触 [OK/NG]   C11 1コマ目=8コマ目 [OK/NG]
D12 実アルファ [OK/NG]   D13 等分 [OK/NG]
持ち物・装飾品の一覧: ____
```

- 全キャラ分を1枚に並べた確認シート（コマ境界と中央70%の範囲に線）も添付する。
- 不合格が出たキャラは、そのキャラだけ再生成する。

## 5. 組み込み側の作業（生成担当は不要）

- 再パッキング: `node scripts/pack-prayer-sheets.cjs scripts/prayer-sources-all.json`（`SHARP_MODULE` で sharp を指定）。
- パッキング後の `rei.webp` / `hakushu.webp`（4112×514）を差し替え、`prayer-v2/packing-report.json` を更新する。
- もびぼう（mobibou）は現在、既存の礼・拍手シートを再利用している。今回の再生成に含める場合は、
  `scripts/prayer-sources-all.json` の mobibou 定義を `source` 形式に直す。

## 6. 機械チェック（納品前に必ず実行する）

```bash
node scripts/check-sprite-sheet.cjs prayer <納品ディレクトリ> --review <確認シート出力先>
```

- `<納品ディレクトリ>/<id>/source.png` の構成で置く。sharpが必要（`SHARP_MODULE` でパス指定可）。
- 判定する項目: 8×2の寸法、実アルファ、中央70%の外の不透明（見切れ）、上下16px以内、別の断片、
  足元・直立コマの背丈・中心のずれ、各行の1コマ目と8コマ目が同じ姿勢か、拍手の行で色が消えたコマ。
- **FAIL が1つでもあれば不合格**。WARN は確認シートで目視する。
- **持ち物の消え（もびりんのパイプ等）は自動では確実に判定できない**。確認シートで全16コマを必ず見る。
  礼の深さ、拍手の接触、同一性も目視。
- このチェックは生成直後の `source.png` 用。パック後の `rei.webp` / `hakushu.webp` では「中央70%」が全件外れる。
