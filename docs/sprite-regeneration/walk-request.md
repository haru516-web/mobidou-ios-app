# 依頼書A: 歩行スプライトシートの再生成（全21体）

別セッション・別担当で、礼拝（依頼書B）と並行して進められる。この文書だけで完結する。

## 1. 何が問題か

現行の `assets/mobies/pilgrimage-walk/{id}.webp` は横4コマ（contact → down → passing → up）で、
**同じ片足だけを出して戻し、また同じ足を出す**動きになっている。歩いているように見えない。
一部のキャラは、シートの隣のコマの一部が写り込んでいる（ウィジェットのプレビューで確認済み）。

## 2. 作るもの

対象は全21体。`assets/mobies/pilgrimage-walk/` に同じ名前で置き換える。

| 区分 | id |
|---|---|
| 通常17 | mobirin mobichi yami mobiyan mobiyura reomoby potemoby mobibou babumoby bearmobby boymobby dogmobby ojimobby reamobby shikamobby uyumobby wolfmobby |
| イベント4 | shotamobby satomimobby norikomobby yasumobby |

キャラの同一性の基準は、通常画像（`assets/mobies/{id}.webp` / `.png`。`scripts/prayer-sources-all.json` に対応表）と、現行の歩行シート。

### 仕様

- **横8コマ × 1行、1コマ 384 × 1024 px、全体 3072 × 1024 px**（現行は4コマ。コマ数が変わる）。
- 右向きの横姿勢、全身がコマ内に収まる。実アルファ透明。文字・枠・仕切り線・床・影・透かしなし。
- コマの順序（**左右の足が交互に出る1歩行周期**）:

| コマ | 内容 |
|---|---|
| 1 | 右足が前で接地（contact-R） |
| 2 | 体が沈む（down-R） |
| 3 | 左足が体の下を通過（passing-R→L） |
| 4 | 体が上がる（up-R） |
| 5 | 左足が前で接地（contact-L） |
| 6 | 体が沈む（down-L） |
| 7 | 右足が体の下を通過（passing-L→R） |
| 8 | 体が上がる（up-L） |

- コマ8の次はコマ1に戻る。**8→1の継ぎ目で動きが飛ばない**こと（ループ再生される）。
- 腕を振るキャラは、足と逆の腕が前に出る。腕のないキャラ・足の見えないキャラ（ころころ転がる、ふわふわ浮く等）は、
  元の移動の仕方を保ったまま、**前半4コマと後半4コマで左右対称の位相差**がつくようにする（2歩=1周期に見えること）。
- 座り姿勢のキャラは座りのままで、体の揺れと手足の動きで歩きを表す。立たせない。

## 3. 審査基準（すべて満たすこと。1つでも外れたら不合格）

### A. 動き
1. 8コマ連続再生して、**左右の足が交互に出ている**（同じ足が2回続けて前に出ない）。
2. 前半4コマと後半4コマが、左右を入れ替えただけの動きになっている（足以外の特徴は入れ替えない）。
3. 隣り合うコマで、足の位置・体の高さが急に飛ばない。体の上下動は全体の高さの2〜6%の範囲。
4. コマ8→コマ1が滑らかにつながる。

### B. コマの境界（写り込み・見切れ）
5. **各コマの左右端から16px以内に不透明ピクセルがない**（手・しっぽ・耳・持ち物を含む）。
6. **隣のコマの断片が一切ない**。コマ内で最大の連結成分以外の不透明ピクセルがない（小さな点・かけらも不可）。
7. コマ間に線・段差・色の帯がない。

### C. 一貫性
8. 全コマで同じ縮尺。足元の接地線が全コマで同じ高さ（±3px）。
9. 体の中心の左右のずれは±6px以内。
10. **持ち物・装飾品がどのコマでも消えない／形が変わらない**（例: もびりんのパイプ、帽子、リュック、マント、キーホルダー、鈴）。
11. 毛色・顔・目（カメラレンズの目）・十字ボタン・衣装が元のキャラと同一。コマごとに別人になっていない。
12. 画風は通常画像と同じ質感（ぬいぐるみの毛並み）。コマによって解像感が変わらない。

### D. 技術
13. PNG、RGBA、実アルファ。チェッカー模様を焼き込まない。背景の縁にハローや白フチがない。
14. 3072 × 1024 px 厳守。コマ境界は384px刻み。

## 4. 納品と自己審査

- 納品物: `{id}.png`（3072×1024）。変換は `.webp` に別途。**原本PNGも残す**。
- キャラごとに、次の自己審査表を埋めて添付する。空欄があるものは受け取らない。

```
id: ____
A1 左右の足が交互 [OK/NG]   A2 前半後半が左右入替 [OK/NG]   A3 コマ間の飛びなし [OK/NG]   A4 ループ継ぎ目 [OK/NG]
B5 端16px以内に不透明なし [OK/NG]   B6 他コマの断片なし [OK/NG]   B7 線・帯なし [OK/NG]
C8 縮尺・接地線 [OK/NG]   C9 中心ずれ [OK/NG]   C10 持ち物が全コマにある [OK/NG]   C11 同一性 [OK/NG]   C12 質感 [OK/NG]
D13 実アルファ [OK/NG]   D14 寸法 [OK/NG]
備考（持ち物・特徴の一覧）: ____
```

- 全キャラ分を1枚に並べた確認シート（コマ境界に赤線）も添付する。目視確認はこの1枚で行う。
- 不合格が出たキャラは、そのキャラだけ再生成する（全体を作り直さない）。

## 5. 組み込み側の作業（生成担当は不要）

アプリは、シートごとの計測値（`pilgrimageSpriteMetrics.json` の `columns`）からコマ数を読むようにしてある。
4コマと8コマが混在していても動くので、**1体ずつ差し替えられる**。差し替えるたびに、アプリ担当が次を行う。

1. `assets/mobies/pilgrimage-walk/{id}.webp` を置き換える（PNG納品の場合は `.png` のまま置いてもよい）。
2. `SHARP_MODULE=... node scripts/inspect-pilgrimage-sprites.cjs` で計測値を更新する（幅÷384でコマ数を決める）。
3. `SHARP_MODULE=... node scripts/build-widget-frames.cjs` でウィジェット用フレームを作り直す。

`FloatingMobby` / `HomeWidgetArtwork` / `PilgrimageAward` / ウィジェットは、コマ数に合わせて自動で再生する。

## 6. 機械チェック（納品前に必ず実行する）

```bash
node scripts/check-sprite-sheet.cjs walk <納品ディレクトリ> --review <確認シート出力先>
```

- 3072×1024の `{id}.png` を置いたディレクトリを指定する。sharpが必要（`SHARP_MODULE` でパス指定可）。
- 判定する項目: 寸法、実アルファ、左右端16px以内の不透明、別の断片、接地線・背丈・中心のずれ、
  コマ間の変化の大きさ、ループの継ぎ目、前半と後半が同じでないこと（同じ足の繰り返し）。
- **FAIL が1つでもあれば不合格**。WARN は確認シートで目視する。
- 機械で判定できないもの（左右の足が本当に交互か、持ち物の形、同一性）は、確認シートで必ず見る。
- 現行シート（4コマ）は `--columns 4` で試せる。全21体が不合格になる（基準の確認用）。
