# もび道 v3 設計書: 課金・ガチャ・サーバー・イベント

作成 2026-09-30。決定事項と、未決定事項（末尾）を分けて記す。価格・手数料・法規は公開前に必ず一次情報で再確認する。

## 1. 方針

- サーバーは **Cloudflare（Workers + D1 + R2 + 静的JSON）**。コストは最小。無料枠で止まる設計（課金が膨らまない）。
- 個人の巡礼は端末内で完結（サーバー費ゼロ）。サーバーが関わるのは、課金・ガチャ・運営ギフト・フレンド・イベント合算のみ。
- 現在のモビー17体は同梱。**追加分はR2からダウンロード**。
- 公開前に、下記すべてを実装する。ソーシャルの公開前確認は memory `pre-release-social-gating` を参照。

## 2. 巡礼

- 巡礼は「恒常」と「イベント」に分ける。データ化して、追加のたびにコードを触らない。
  - 恒常: 常時遊べる。今後も継続して追加する（御朱印×モビーが核）。
  - イベント: 期間あり。フレンドの合算歩数でイベント専用マップを回る。御朱印・ミニチュア・新モビーが出る。
- イベント枠は、未開放の枠（鍵札を使った作り込みのデザイン）として先に見せる。日付や内容は約束しない。
- マップ切り替えは今も可能で、途中経過はルートごとに保存され、選び直すと続きから再開する（`selectRoute`）。
- **再巡礼**: 結願済みのルートを選び直すと、歩数は0から積み直す。ただし**結願の認定は維持**する。
  - 御朱印を所持済みなら「もう持ってるよ」と短い演出に切り替える。
  - 結願報酬（称号・結願印・無料ガチャ1回）は**初回のみ**。
- 称号: 各巡礼の結願時に授かる名前（例「神域を訪ねた人」「雲上の旅人」）。結願印・満願証と一緒に授与される。

## 3. ミニチュアキーホルダー

| 項目 | 仕様 |
|---|---|
| 所持上限 | 1個（御朱印も1）。旧データの2個以上は1に丸める移行が必要 |
| 抽選タイミング | 寺社に到達した演出の時だけ |
| 所持済み | 「もう持ってるよ」を表示。抽選しない |
| 未所持 | 到達のたびに抽選（再巡礼でも）。前回の結果とは独立 |
| 確率 | 無料 10% / 月額プラン 50% |
| 交換券 | 外れたその場で、使うか選ぶ。過去の外れには使えない。月をまたぐと消える |
| コンプ | 巡礼・ミニチュアの追加とともに対象が増えるため、簡単には終わらない |

旧仕様の `pending` / `declined` 状態と、一度きりの抽選記録（`rolls`）は廃止する。

### 月額プラン（自動更新サブスクリプション）

| プラン | 価格 | 内容 |
|---|---|---|
| ライト | 120円/月 | 確率50% |
| プラス | 300円/月 | 確率50% + 交換券10枚/月（繰越なし） |

- 確率50%は、契約中に到達した寺社にだけ適用する（遡及なし）。
- 契約状態は端末のStoreKit 2で判定する。交換券の月次付与と残数は**サーバーが正**とし、二重付与を防ぐ。
- 残り枚数と有効期限を常に画面に表示する。
- 日本の定期購入の表示要件（特定商取引法・Appleの審査要件）を満たす画面を用意する。

## 4. 御朱印帳の表紙

- 表紙パス（表紙替え券）は**廃止**。購入導線・券・関連UIを削除する。
- 12種の専用表紙は、**そのルートの初回結願報酬**として解放する。

## 5. モビーのガチャ

| 項目 | 仕様 |
|---|---|
| 価格 | 1回 250円 / 5連 1,000円 |
| 無料 | 各巡礼の**初回結願**で1回。再巡礼では付与しない |
| 対象 | モビーのみ（キーホルダー・御朱印は対象外） |
| 無料の対象プール | 恒常プールのみ。イベントの新モビーは有償・イベント専用（案） |
| 重複 | 小さいモビーとしてメインの周りに表示する案（検討中） |
| 抽選 | 有償はサーバーで行う（基準の実装は `src/services/gacha.ts`）。排出履歴を保存 |
| 確率 | 対象全体（最初の1体・重複を含む）から**完全に均等**。提供割合を画面に表示 |
| 天井 | **有償25回ごと**（5連×5回）に、未所持の1体を確定。無料は数えない。未所持がなければ通常抽選 |
| 最初の1体 | 初回のチュートリアルで**全体から1体を選ぶ**。以降は完全抽選（初期の選べる数枠は作らない） |

## 6. イベント（フレンド合算）

- フレンドと合算した歩数で、イベント専用マップを回る。人数は2〜4人程度、ソロ参加も可能にする。
- 歩数の送信は**1日1回**。その日の受付は**当日20:00〜翌日20:00（日本時間・サーバー時刻で判定）**で、累計値を送り二重加算を防ぐ。20:00に開けなかった日も翌日20:00前までに送れば、その日の分として受け付ける（決定済み）。負荷は端末ごとに送信時刻がばらけるため自然に分散する。
- 個人の巡礼はリアルタイムのまま。20時更新はイベント・フレンド合算のみ。
- 不正対策: HealthKitの手入力データを除外する。1日の上限を設ける。日付はサーバー時刻で判定する。

## 7. 画像とデータの配信

- 新モビー・イベント画像は、R2から取得して端末に保存する（取り出し料金が無料）。
- 「モビーパック」: 1体分の画像、動作フレーム、位置・寸法のJSON、名前、一言を1つにまとめた決まった形式。1体あたりの容量に上限を決める（目安3〜5MB）。
- モビー一覧は、サーバーのカタログJSONから取得する。`PetId` は固定の名前から「一覧に載っている名前」に広げる。
- 取得に失敗したときの再試行と案内、保存先（iOSに消されない場所）、ファイルのハッシュ検証を用意する。
- Appleの規約上、データ（画像・JSON）の取得は可。実行コードの取得は不可。

## 8. サーバー（Cloudflare）

### テーブル（D1）

| テーブル | 主な列 |
|---|---|
| users | id(匿名ID), secret_hash, friend_code, name, pet_id, goshuin_count, route_name, last_seen |
| friendships | user_id, friend_id, created_at |
| friend_requests | id, from_id, to_id, status, created_at |
| purchases | apple_transaction_id(主キー), user_id, product_id, granted_at, revoked_at |
| entitlements | user_id, plan, period_start, period_end, tickets_granted_period |
| ticket_ledger | id, user_id, delta, reason, ref(取引ID・期間) |
| gift_claims | user_id, gift_id（**一意制約**） |
| gacha_pulls | id, user_id, pool_id, result_pet_id, pulled_at, paid |
| gacha_state | user_id, pool_id, pity_counter |
| events | id, name, starts_at, ends_at, map_id |
| event_teams / event_members / event_steps | チーム、所属、日別の累計歩数（一意: user×event×日） |

### API

| 用途 | エンドポイント |
|---|---|
| 匿名登録 | POST /auth/register |
| 運営ギフト一覧（静的JSON） | GET /gifts.json |
| ギフト受け取り | POST /gifts/:id/claim（一意制約で二重受取を防ぐ） |
| フレンド | GET /friends、POST /friend-requests、POST /friend-requests/:id/answer |
| 購入検証 | POST /purchases/verify（StoreKit 2 JWSを検証） |
| サブスク通知 | POST /apple/notifications（App Store Server Notifications） |
| 交換券 | POST /tickets/consume |
| ガチャ | POST /gacha/pull { pool, count } |
| モビーカタログ | GET /catalog.json |
| イベント歩数 | POST /events/:id/steps { cumulative } |
| イベント状況 | GET /events/:id |

### 不正・二重付与対策

- 購入: Appleの取引IDを主キーにする。署名（JWS）を検証する。
- ギフト: user×giftの一意制約。受け取りは1回の書き込みで確定する。
- 交換券: サーバー側の台帳（ticket_ledger）を正とする。
- 歩数: 累計値のみ受け付ける。時刻はサーバー基準。
- 端末変更: Appleの購入復元と、引き継ぎコードで対応する。
