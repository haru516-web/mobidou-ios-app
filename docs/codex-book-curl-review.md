# Codex 評価依頼: 御朱印帳のページカールで、御朱印と右側のテキストが出ない問題

評価だけをお願いします。コードは変更しないでください。

## 症状
iOSの開発ビルドで、御朱印帳の見開きを開くと、右ページの御朱印と、その右側（下）のテキストが表示されない。ブラウザー表示では「左に御朱印、右に説明文」の見開きが出る。10/8にも「御朱印帳画像がすぐ消える」「ページカールが効いていない」という報告があった。

## 仕組み
- iOS開発ビルドでは、見開きをネイティブのページカール（`UIPageViewController` の `pageCurl`）で表示する。
- ネイティブ側はReactの画面を直接描けないので、アプリが見開きを1枚ずつPNGに撮り（`react-native-view-shot`）、画像として渡す。
- 画像が揃わない、または撮れないときは、アプリ自前の `SimulatedBookPageTurn` に切り替える。

## 対象
- コミット: `f1e5453`（ブランチ `claude/server-connect` と `claude/events` の両方にある。`git show f1e5453`）
- `src/components/BookPageTurn.tsx`（`SnapshotCurlBookPageTurn`）
- `src/services/captureView.ios.ts`
- `src/components/NativeBookPageTurn.ios.tsx`、`modules/mobi-page-curl`（ネイティブ側）
- 導入時のコミット: `215e9b1`

## 仮説と修正（Claude側）
- 仮説: 撮影用ビューを画面の右外（`left: size.width + 40`）に置いていたため、iOSが描かず、ほぼ空の画像になった。
- 修正1: 撮影用ビューを、本の真下（`left: 0`、重なる位置）に移した。
- 修正2: 撮った画像のファイルが30KB未満なら、エラーにしてフォールバックする。

実機で修正後の表示を確認した記録はない。仮説は未検証。

## 評価してほしい点
1. 仮説は妥当か。他に考えられる原因はないか（画像の読み込みタイミング、フォント、`collapsable`、`renderSpread` の再描画、撮影時にビューが重なる／隠れる、など）。
2. 修正1は、iOSで確実に描かれるか。本の下に重ねたビューが、可視の見開きに干渉しないか。
3. 30KBの閾値は妥当か。正常でも30KB未満になる見開き（御朱印が少ないページ、空のページ）はないか。
4. 撮影に失敗したとき、フォールバックの `SimulatedBookPageTurn` で、御朱印と右側のテキストが確実に出るか。
5. 「画像がすぐ消える」現象が起きうる箇所（画像のキャッシュ、`tmpfile` の削除、`uris` の再計算など）はないか。
6. 確認する手順として、実機でどこを見れば原因を切り分けられるか。
