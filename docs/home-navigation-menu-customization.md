## 1. ホームの通常表示

通常のホームは、既存のブランドヘッダー（設定を含む）、吹き出し付きの選択中モビー、その直下のホームカード2枚、下部ナビだけで構成する。

ホームカードの左右位置は保存された選択順に従う。カードの下へフッター文、追加カード、歩数ボタン、4項目目のウィジェットを並べない。

```text
ブランド・設定
吹き出し
選択中モビー
┌──────────────┬──────────────┐
│ 左カード     │ 右カード     │
└──────────────┴──────────────┘
下部ナビ
```

2枚は同じ高さの2列カードとし、コンテンツ幅が狭くなっても横2列を維持する。文字は省略・折り返しを使ってカード内に収め、既存の御朱印画像・巡礼画像・実データを再利用する。

## 2. ホームカードの候補

カスタムで選べる候補は次の4つ。通常ホームには、このうち選択された2つだけを表示する。

| ID | 表示 | 内容と導線 |
| --- | --- | --- |
| `goshuin` | 御朱印 | 現在の巡礼で最新または最初の適切な御朱印を表示。タップで既存の御朱印詳細、詳細から御朱印帳へ移動できる |
| `miniature` | 巡礼ミニチュア | 現在選択中の巡礼と既存巡礼画像を表示。タップで既存の巡礼選択を開き、コースを選び直せる |
| `map` | 巡礼マップ | 現在の巡礼を背景にしたマップカード。タップで既存のおでかけ画面の巡礼マップを開く |
| `steps` | 歩数count | 現在の歩数、次の御朱印までの残り歩数、進捗を表示。タップで既存のおでかけ画面の歩数へ移動する |

## 3. カスタム操作

下部ナビ右側の独立した四角4つの `メニュー` ボタンから `ホーム画面カスタム` を開く。

- カスタム画面には、左枠・右枠の現在の2選択と、4候補を表示する
- 左枠または右枠を選んでから候補をタップすると、その枠を置き換える
- 既にもう一方の枠に選ばれている候補をタップした場合は左右を入れ替える。重複は作らない
- `左右を入れ替え` でも左右順を交換できる
- `完了` は2枠の選択と順序を保存して閉じる
- ヘッダーの `×` または Android の戻る操作は、編集中の変更を破棄して閉じる
- 背景タップでは閉じない

初期値は `goshuin`（左）+ `miniature`（右）。

## 4. 保存と旧データ移行

保存先は既存の端末ローカルキー `@mobidou/journey/v1`。保存する値は次の2要素タプルである。

```ts
type HomeWidgetId = 'goshuin' | 'miniature' | 'map' | 'steps';
type HomeWidgetOrder = [HomeWidgetId, HomeWidgetId];
```

4候補から必ず異なる2つを保持する。旧バージョンの4要素 `homeWidgetOrder` が残っている場合は、配列を左から読み、妥当な異なるIDの先頭2つへ移行する。2つ集められない不正値は初期値へ戻す。未知の値・重複値でホームに同じカードを2枚表示しない。

編集中の選択は一時状態に留め、`完了` を押したときだけ保存する。

## 5. 下部ナビとメニュー

下部には左から次の主要ナビ4項目を置く。

1. `ホーム`
2. `御朱印帳`
3. `おでかけ`
4. `コレクション`

`モビー` は常設タブにせず、右側で視覚的に分離した独立 `メニュー` ボタンから選ぶ。ボタンは四角4つのライブUIで、開閉時に枠線・色・向きを変える。展開時は浅い円弧上に `ホーム画面カスタム` と `モビーを選ぶ` を表示し、どちらかを選ぶとメニューを閉じる。

## 6. モビー選択

`モビーを選ぶ` は既存の `PET_CHARACTERS` 18体を表示し、既存画像・背景・アクセントカラーを再利用する。タップでは一時選択だけを変更し、`決定` で `data.pet` を保存する。`閉じる` または Android の戻る操作では一時選択を破棄する。

モビー選択中はモビーを見せ、ホームカード列を背後で隠す。ホームカスタム中はモビーを背後で隠し、ホームカード列は表示する。2つのポップアップは同時に表示しない。

## 7. アクセシビリティとモーション

- 主要ナビ、メニュー、2つのメニューアクション、左右枠、4候補、完了・閉じる・決定に日本語のアクセシブルラベルを付ける
- 候補は選択状態と左右枠を読み上げる
- Reduced Motion では移動を短いフェード（160ms）にする
- タップ領域はカード、枠、ボタンともに十分な大きさを確保する

## 9. Apple風ナビとホームカード拡大表示

下部ナビは、左の4項目と右の `メニュー` を同じ親背景にまとめず、別々の兄弟コンテナとして表示する。両方ともiPhone筐体のような大きく滑らかな角丸（iOSでは利用可能な場合 `borderCurve: 'continuous'`、Web/Androidでは同等の `borderRadius`）を使い、ピル状にはしない。

メニューを開くと、左ナビ全体がレイアウトを変えずに視覚的に少し縮み、メニューボタンの中心を基準に2つの正方形アクションが浅い上向き円弧に展開する。2アクションは同寸・同じ角丸で、互いに重ならない。

ホームの選択済み2カードは直接画面遷移せず、タップした種類だけを大きく見せる排他的な拡大ポップアップを開く。御朱印は御朱印詳細／御朱印帳、巡礼ミニチュアは巡礼選択、巡礼マップは巡礼マップ、歩数countはおでかけ歩数への導線を備える。ポップアップは明示的な `閉じる`、Android back、Web Escapeでのみ閉じ、背景タップでは閉じない。表示中は下層ナビを操作できず、Reduced Motionでは短いフェードにする。

ポップアップ表示中はホームの `ScrollView` と下部ナビを `accessibilityElementsHidden`／`importantForAccessibility="no-hide-descendants"`／`aria-hidden` でアクセシビリティツリーから隠し、`pointerEvents="none"` と `scrollEnabled={false}` で下層操作も止める。拡大ポップアップ自身は `role="dialog"`、`aria-modal`、`accessibilityViewIsModal` と日本語ラベルを持ち、閉じる・二次導線の操作要素を残す。
